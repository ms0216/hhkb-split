# 本体基板の配線を自動配線器に委ねる — 設計

**日付**: 2026-08-08
**対象**: `tools/gen_pcb.py`（本体基板 左/右）
**対象外**: `tools/gen_daughterboard.py`（子基板は違反 0。触らない）

---

## なぜ作り直すのか

引き継ぎ書は「残っているのは引き回しの微調整だけ」と書いていた。
**その診断が誤っている。** 残り 54 件（左 25 / 右 29）は微調整で
消える性質のものではない。

### 根拠 1: 手書きルータには衝突判定が無い

DRC の実測内訳に、**任意のネット対の短絡**が並ぶ。

```
２つのネットを短絡するアイテム (ネット ROW3 と COL1)
２つのネットを短絡するアイテム (ネット ROW4 と ROW1)
２つのネットを短絡するアイテム (ネット COL2 と ROW1)
Tracks crossing  × 6
```

`ROW4` と `ROW1` が短絡するのは、経路の良し悪しの問題ではない。
**自分がすでに引いた線を見ていない**ことの帰結である。
衝突判定を持つルータは、これを構造的に出せない。

証拠はコードにもある。`_fcu_verticals` は「表面の縦配線を後から拾って
避ける」という後付けのパッチで、まさにその盲点を塞ぐために足された。
内層 2 のレーンどうしの交差（`Tracks crossing`）には、同じパッチが
まだ無い。**盲点をひとつずつパッチで塞いでいる。**

### 根拠 2: 局所探索で大域問題を解こうとしている

これまでの手はすべて「マジックナンバーを 3 つ測って良い方を採る」形。

| 定数 | 試した値 | 採った値 |
|---|---|---|
| `PLACE` の y 逃がし | -1.8 / -2.6 / -3.4 | -1.8 |
| `_clear_x` の `keep` | 1.0 / 1.6 / 2.0 / 2.5 | 2.0 |
| `_SOCK_MID` | -2.3 / +2.3 | +2.3 |

リップアップも大域的なコスト関数も無いので、ひとつ潰すと別が出る。
実際に 25→34、24→144、23→36 と戻した記録が残っている。
**「DRC の件数が実行ごとにゆらぐ」のも、解に近づいていない徴候。**

### 根拠 3: U1 は「寄っている」のではなく物理的に入っていない

コートヤードを実測した。

| | コートヤード | 帯 9.25mm に対して |
|---|---|---|
| `SOIC-16_3.9x9.9mm_P1.27mm`（現在） | 7.49 × **10.49mm** | **1.24mm はみ出す** |
| `TSSOP-16_4.4x5mm_P0.65mm` | 7.79 × **5.59mm** | 3.66mm 余る |

`PLACE` の `-1.8` は、**どちら側にはみ出すかを選んでいるだけ**である。
これは調整の問題ではなく算数の問題で、調整では絶対に 0 にならない。

74HC595 は TSSOP-16 で JLCPCB にある。

## 実測で確かめた前提

推測ではなく、手元で走らせて確認した事実だけを設計の前提に置く。

| 確かめたこと | 結果 |
|---|---|
| `pcbnew.ExportSpecctraDSN` / `ImportSpecctraSES` | KiCad 10.0.5 に**ある**。左基板の書き出し成功 |
| DSN が 4 層を運ぶか | 運ぶ（F.Cu / In1.Cu / In2.Cu / B.Cu） |
| DSN がクリアランス規則を運ぶか | 運ぶ（`(rule (width 200) (clearance 200))`）。ただし**その 200 は KiCad の既定値**で、この案件が設定した値ではない（下記「ネットクラスを明示する」） |
| DSN が NPTH 穴を運ぶか | 運ぶ（keepout 132 個） |
| GND ベタの扱い | **`(plane GND (polygon In1.Cu ...))` として運ぶ。** Freerouting は GND を配線せず面に任せる |
| 既存配線の扱い | `(wiring ...)` に載る → **未配線の基板を渡す必要がある** |
| ツールチェーン | OpenJDK 26 + Freerouting v2.3.0 導入済み。`-de` / `-do` / `-mp` でヘッドレス動作 |

**GND が面として渡ることは、この設計にとって重要。** いまの
「GND はベタで受けて配線しない」という思想が、自動配線器にそのまま
伝わる。作り直しで失われない。

## 設計

### パイプライン

```
tools/gen_pcb.py       配置・ネット・ゾーン・JLCPCB 規則（配線は持たない）
      ↓  pcb/unrouted/hhkb_split_{half}.kicad_pcb
tools/autoroute.py     DSN 書き出し → Freerouting → SES 取り込み → 保存
      ↓  pcb/hhkb_split_{half}.kicad_pcb        （最終・パスは従来どおり）
tools/drc.py           変更なし
```

最終成果物のパスを変えないので、`drc.py`・ガーバー出力・既存の検査は
そのまま動く。

### `gen_pcb.py` から削るもの

| 対象 | 行 |
|---|---|
| `_route` | 178–284 |
| `_fcu_verticals` | 441–455 |
| `_clear_x` | 458–483 |
| `_route_electronics` | 486–585 |
| `_nearest_via` | 587–597 |
| `_link` | 599–628 |
| `_track` / `_via` / `_pad` | 154–175 |
| 定数 `COL_VIA_DX` / `LANE_CENTER` / `LANE_SPACING` | 131–151 |

`_track` / `_via` / `_pad` は**配線関数の中でしか使われていない**
（実測: 呼び出しは 186–627 行のみ）ので、一緒に消える。
`_pour`（790 行の GND ベタ）は残す。

合計およそ 470 行。`build()` からは `_route(...)` と
`_route_electronics(...)` の 2 行の呼び出しを外す。

**残る約 340 行が、この案件で本当に価値のある部分。**
`interface.py` に縛られた決定的な配置、`matrix.py` 経由でファームウェアと
同期したネット、JLCPCB の設計規則、シルク線幅の担保、裏面のキー名。
ここは一切触らない。

### ネットクラスを明示する（潜在的な穴を塞ぐ）

`TRACK_W` / `VIA_D` / `VIA_DRILL` は消さず、**ネットクラスの値として
基板に書き込む**。理由は、いま書き込まれていないから。

`_apply_jlcpcb_rules` は**最小値しか設定していない**
（`m_TrackMinWidth`・`m_MinClearance` ほか）。ネットクラスの
線幅・クリアランス・ビア径は一度も設定していない。DSN に載っていた
`(width 200) (clearance 200)` と `Via[0-3]_600:300_um` は
**KiCad の既定値**であって、この案件が選んだ値ではない。
`TRACK_W = 0.2` と偶然一致していただけである。

手書きルータは `TRACK_W` を直接読んでいたので実害が出なかったが、
**自動配線器はネットクラスしか見ない。** 既定値が変われば黙って
別の線幅で配線される。

そこで `_apply_jlcpcb_rules` に既定ネットクラスの設定を足す。

| | 値 | 根拠 |
|---|---|---|
| 線幅 | 0.2mm | 既存 `TRACK_W`。JLCPCB 最小 0.127mm に対する余裕 |
| クリアランス | 0.2mm | 既存 DRC が使っていた値 |
| ビア径 / ドリル | 0.6 / 0.3mm | 既存 `VIA_D` / `VIA_DRILL` |

これで規則の出どころが 1 箇所になり、DSN は構造上その値を運ぶ。
`autoroute.py` 側に規則を渡す仕組みは要らない。

### `tools/autoroute.py`

```
for half in ("left", "right"):
    1. pcb/unrouted/hhkb_split_{half}.kicad_pcb を読む
    2. pcbnew.ExportSpecctraDSN で .dsn を書く
    3. java -jar freerouting.jar -de {dsn} -do {ses} -mp {passes}
    4. pcbnew.ImportSpecctraSES で取り込む
    5. ゾーンを塗り直して pcb/hhkb_split_{half}.kicad_pcb に保存
    6. 未配線基板の sha256 を記録に残す
```

**手順 5 のゾーン塗り直しを省かない。** 引き継ぎ書に
「『ゾーンを足した』と『塗られた』は別」という教訓が 2 回出てくる
（4 層化のとき、V3V3 の島のとき）。SES 取り込みでビアが増えた後、
GND ベタを塗り直さないと同じ罠を踏む。

Freerouting の場所は環境変数 `FREEROUTING_JAR` で上書きでき、
既定は `~/.local/share/freerouting/freerouting-2.3.0.jar`。
見つからないときは、入手方法を示して落ちる（黙って進まない）。

### 陳腐化の検出

`drc.py` はすでに「基板の sha256 を記録に埋め、CI で照合する」形をとる。
**同じ型を一段手前にも入れる。** 新しい仕組みは作らない。

`pcb/route_{half}.json` に、その配線が**どの未配線基板から作られたか**を
記録する。`test_pcb.py` が照合し、ずれていれば落ちる。

これで検出できるようになるのは「**配置を変えたのに配線し直していない**」。
いまは検出できない。

### 部品の変更（自動配線とは別ステップ）

`ELEC_FP["74HC595"]` を `("Package_SO", "TSSOP-16_4.4x5mm_P0.65mm")` へ。
`PLACE` の 3 番目の要素（`-1.8` の逃がし）は不要になるはずなので外す。

**この変更は自動配線より先に、単独で DRC を測って記録する。**
混ぜると、どちらが効いたのか分からなくなる。

## 検査

この案件の作法どおり、「通ること」ではなく「**効いていること**」まで見る。
**どの検査も、故意に壊して落ちることを確かめてから足す。**

| 検査 | 何を守るか | 故意に壊す方法 |
|---|---|---|
| 電子部品のコートヤードが帯 9.25mm の内側にある | **算数で入らない部品を二度と見逃さない** | `ELEC_FP` を `SOIC-16` に戻す |
| 配線の記録が現在の未配線基板から作られている | 配置を変えたのに配線し直していない | 未配線基板を 1 バイト変える |
| ネットクラスの線幅・クリアランス・ビア径が意図した値である | **自動配線器が既定値で配線する**のを防ぐ | ネットクラスの設定行を消す（既定値と一致するので、値の比較だけでは落ちない。**設定が存在すること**を見る） |
| 未配線 0・違反 0（既存 `drc.py` の記録経由） | 回路と形の正しさ | 既存 |

`WIP_BOARDS` は DRC が 0 になった時点で空にする。
`test_the_unfinished_boards_are_declared` が「綺麗になったのに残っている」
状態を検出するので、忘れることはない。

**接頭辞での走査をしない。** 新しい検査で部品を拾うときは
`re.fullmatch(r"D\d+")` のように絞る。`D` / `SW` で拾うと
`D_PWR` / `SW_PWR` を巻き込む（引き継ぎ書によれば同じ事故が 3 回）。

## やらないこと

| | 理由 |
|---|---|
| Freerouting の GUI・対話モード | ヘッドレスで足りる |
| CI での自動配線 | DRC と同じく手元専用。Java は CI に入れない。CI は記録の鮮度だけ見る |
| 配置の自動探索（`_obstacles` / `_free_x`） | 引き継ぎ書が「23→36 に悪化」と実測済み。TSSOP で帯に収まれば不要 |
| 子基板 (`gen_daughterboard.py`) の作り直し | すでに違反 0。触る理由が無い |
| クリアランス規則の緩和 | 違反の 8 割が 0.1mm 以下と実測済み。規則の問題ではない |

## 失敗したときの判断

Freerouting が 100% に届かない、あるいは DRC が現状（54 件）より
悪い場合に、なし崩しで手書きルータへ戻さないための線引き。

1. **未配線が残る** → パス数を上げ、`-us global` を試す。
   それでも残るなら、残ったネットだけを手で引く（全部を手で引く形には戻さない）
2. **DRC 違反が出る** → 違反の中身を見る。Freerouting は自分の
   クリアランス規則の中で解くので、出るとすれば DSN に渡っていない
   規則（アニュラリング・外形までの距離）。**規則を渡す側を直す**
3. **どちらも解決しない** → この設計書に実測値とともに追記し、
   引き継ぎ書の「試して失敗した手」に移す。手書きルータへ戻す判断は
   そのあと

**判断の材料は毎回 DRC の JSON。** 印象で戻さない。
