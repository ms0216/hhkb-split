## 2. K 案の最終形（仕様 v7）

XIAO が I2C の主、ポッドの ATtiny1616 が従。**XIAO が読みに行った瞬間だけ ATtiny が起きて、スティックを測って返す。**

- 静止中は毎秒 4 回、動かしている間は毎秒 60〜100 回読む。System OFF 中は読まない。
- クリックはポッドが数えて「回数」で返す。化けが無く 250ms 以内に読めていれば、回数は実物と一致する。読み落としが続くと取りこぼす（幻のクリックにはしない）。

  （ピン設定・Kconfig・電源管理には手が入る。変わらないことは CI ビルドと受け入れ試験 1 で確かめる。未確認）。
- 左右とも同じ作りで付けられる。付け外しは追加シールドとして `build.yaml` で重ねる。

### 7-1. 右手では「USB 給電中は打ち止めを判定しない」が効いていない（#25b の「解消」は誤り）
- **確認できた事実**: `low_battery_off.c` の USB の門は `CONFIG_ZMK_USB` の中（47・66 行）。右（子機）では ZMK の依存関係でこれが n になる。
  右の CI ビルドログ（2026-09-27 の実行）に警告 "ZMK_USB … was assigned the value 'y' but got the value 'n'" があり、最終の .config にも無い（私も grep で確認）。
  `docs/notes/autonomous-20260903.md` 24 行の「解消…左右とも USB の門が効く」は、設定の代入だけを見たもの。
- **推定（実機未確認）**: 右を USB 給電し、電池が 2.40V 未満なら約 125 秒（初回 65 秒＋60 秒・2 回連続）で soft off。キーでは起きない。
  電源スイッチ OFF の場合は、分圧の読みが 0mV ではなくダイオードの逆漏れ × 2MΩ になるはずで、2.40V を下回るかどうか次第。
- 直し方の案: 門を `CONFIG_USB_DEVICE_STACK` に替える（ZMK 本体の activity.c と同じ条件。右でも usb.c はビルドされている）。未ビルド。
- 隣の件: ZMK は 30 秒無操作で電池の測定を止めるが、こちらのタイマーは古い値を数え続ける。「2 回連続」が実質 1 回になりうる。

### 7-2. XIAO 基板上のフラッシュ（P25Q16H）は 2.3〜3.6V の部品で、検査の対象に入っていない
- **確認できた事実**: データシートで 2.3〜3.6V、待機 18µA（標準）、深い省電力 0.6µA（標準）。`tools/circuit.py` の `IC_SUPPLY_RANGE` と `parts-audit.md` に記載が無い。
  ZMK はこのフラッシュを使わない（設定は内蔵フラッシュ）。ドライバが深い省電力の命令を送るのは suspend のときだけ。
- **仮説（未実測）**: System ON の間、フラッシュは待機 18µA のまま。もしそうなら右 40µA の 45% にあたる。
  起動直後に数行で止めれば最大約 17µA 減り、K 案の増加分と同程度。ただし 2.3V 未満で命令が通る保証は無い。
- 低電圧でフラッシュの停止に失敗すると、スリープと soft off が中止される経路がある（ソースで確認・現象は未確認）。
