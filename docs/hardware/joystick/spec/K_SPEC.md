## 0. 一言で
ポッド上の ATtiny1616 が、キーボードの XIAO から I2C で読まれた瞬間だけ起きて、スティックを測って返す。
それ以外はパワーダウンで寝ている。XIAO 側は System OFF 以外のあいだ、静止中は毎秒 4 回、
動いている間は毎秒 60〜100 回読む。**GPIO SENSE・注意パルス・System OFF からの起床は v1 では使わない。**

## 2. フレーム（ホストが 11 バイト読む・100kHz・アドレス 0x2A）
| byte | 内容 |
|---|---|
| 0 | 0xC3（マジック） |
| 1 | bit7-6 版（= 1。違う版なら捨てて「失敗」に数える）, bit5-4 リセット要因, bit3-1 = 0（**ホストは無視する**。うち 2 つは将来の改良 A・B の対応表示に予約）, bit0 押下中 |
| 2 | **ブート ID**（起動ごとに +1。RAM の .noinit 領域。**電源投入リセット（RSTFR.PORF）のときは、スティックに通電して測った X・Y・T と温度センサの下位ビットでかき混ぜる**。電源断後に同じ値へ戻る事故を 1/256 にする） |
| 3 | 上位 4bit = 押した回数 mod 16、下位 4bit = 離した回数 mod 16 |
| 4 | 測定の通し番号（測るたびに +1） |
| 5-8 | `(T<<20) \| (X<<10) \| Y` の 32bit を**上位バイトから**（T = スティック上端、各 10bit、上位 2bit は 0） |
| 9-10 | CRC-16 over byte0-8、**上位バイトが先**。多項式 0x1021・初期値 0xFFFF・**反転なし（avr-libc の `_crc_xmodem_update`。`_crc_ccitt_update` ではない）**。"123456789" → 0x29B1 |

ホストの受け入れ規則:
1. 長さ・マジック・CRC が合わなければ捨てる。T<64、X>T+8、Y>T+8 も捨てる。
2. (ブート ID, 通し番号) が前回と同じなら捨てる（測り直していないフレーム）。**捨てたフレームはどれも「失敗」に数える。**
3. 次のどれかなら **回数は数えず、押下状態だけ合わせる**: 初回／**不在から戻った最初のフレーム**／ブート ID が変わった／前の正常フレームから **800ms（静止周期 250ms の 3 倍＋50ms）を超えた**／
   通し番号の進み `(seq − 前回) mod 256` が「1 〜 前回からのポーリング回数」の外。
4. それ以外は回数の差分から押し/離しを順に再生する。矛盾したら 3 と同じ扱い。
5. 再生する押し/離しは 16ms 以上あけて出す（出力待ち行列は 32 個まで。不在・固着に入ったら捨てる）。
6. **「不在」に入るときは「離し」を出して押下を解く。**（ゼロ移動は出さない＝差分ゼロのイベントは禁止。SLEEP 直前の離しはホストに届かないので当てにしない。**固着までの時間 5 分 < ZMK のスリープまでの時間**を保つこと）
7. 規則 2 の「前回」は不在を挟んでも覚えておく（同じフレームを不在明けに受け入れない）。
8. **「固着」で離しを出したあとは、押下 0 のフレームを受け入れるか、**同じブート ID のまま**離しの回数が進むまでボタンを無視する**（次の読み出しで押し直さない）。

`tools/stick_pod/proto_model_v6_copy.py` で検証（16 条件・各 40 万フレーム。押しっぱなし＝固着の条件を追加。化け無し・周期 250ms 以下では押し回数が実物と完全一致。検査は「回数の再生で出した押しは、その 2 フレームの間に
実物で起きた押しを超えない」「状態合わせの押しは 1 回まで」「不在なのに押下が残らない」）:
化け無し・3 割破損・単発再起動・リセットの連続・95% 破損・古いフレームの使い回し・連打・抜き差し（押したままも）・全部入りで違反 0。
ブート ID が電源の入れ直しのたびに**必ず同じ値へ戻る**最悪条件だけ、約 800 回の入れ直しで 2〜3 件の幻が残る →
ID を乱数でかき混ぜると 0 件。4bit が一周する 16 クリックは取りこぼす（幻にはならない）。
このモデルは開発中に仕様の穴を 3 つ見つけた（再起動旗の扱い、不在明けの古いフレーム、検査自体の数え方）。

## 3. ポッドのファーム（素の C・avr-gcc＋Microchip ATtiny_DFP）
- ヒューズ: BODCFG=0x08（レベル 1.8V・動作中サンプル・スリープ中オフ）、WDTCFG=0x0B（8 秒・窓なし。0x0A は 4 秒）、
  **SYSCFG0 は書かない**（RESET ピン = UPDI のまま。errata によると実際の出荷値は 0xF6 で、データシートの 0xC4 と予約ビットが違う。読み戻しの照合は定義済みの欄だけで行う。RSTPINCFG を変えると 12V が無いと戻せない）、OSCCFG=0x02、OSCLOCK は立てない。
  書いたら必ず読み戻して照合する。
- クロック: 20MHz を 6 分周（3.33MHz・リセット既定）。CLK_ADC は 4 分周（833kHz。1.5MHz 以下の制約内）。
- タイマ: **RTC.CTRLA は起動時に 1 回だけ書く（RTCEN=1）。PITEN は切らない。**PIT は 1.024kHz 源の 32 周期 = 31.25ms（RTC の busy フラグを待ってから書く）。
  1 秒は 32 回で数える。**5ms の読み出しタイムアウトは TCB0、4ms のチャタリング待ちは TCB1**（重なりうるので分ける）。
- 起動時に RSTFR を読んでフレームのリセット要因へ写し、**読んだら消す**（消さないと要因が積み重なる）。2bit の割り当て: 0=電源投入（PORF 優先）、1=BOD、2=WDT、3=その他（UPDI・ソフト・外部）。
- ブート ID のかき混ぜで温度センサを読むときは 1.1V 基準と長いサンプル時間に切り替えるので、**TWI クライアントを有効にする前に VDD 基準と通常の設定へ戻す**。
- 起動時のボタンは「いまの状態を読むだけ」で、回数は増やさない。
- 既定: 使わないピンは入力バッファ無効（**PB0・PB1・PA0・PA2 は除く**）。PB4/PB5 は DIR を 1 回だけ設定し、OUTSET/OUTCLR=0x30 で同時に動かす。
- **TWI クライアント**: APIEN・DIEN・PIEN を有効。スマートモード（SMEN）は使わない。
  - アドレス一致（読み）: ACK を返す前にスティック通電 → 50µs → ADC（INITDLY=DLY16、T・X・Y）→ 通電を切る →
    先頭 9 バイトを用意して ACK。CRC は送出中に計算して最後の 2 バイトに間に合わせる。SCL の引き伸ばしは約 0.15〜0.3ms。
  - 1 バイト送るには **SDATA に書いてから `SCMD=RESPONSE`**。**読み出しごとの最初のデータ割り込みでは RXACK を見ない**（前回の NACK が残っている）。2 バイト目以降で RXACK=NACK なら `SCMD=COMPTRANS`。（megaTinyCore の Wire.cpp と同じ手順）
  - バイト間は Idle スリープ。11 バイトを超えて読まれたら 0xFF を返す。CRC はバイトを出すたびに畳み込む。
  - STOP、または**アドレス一致から 5ms**（TCB）でパワーダウンへ。5ms で切れたら TWI を無効→有効にして線を離す。
  - **パワーダウンに入ってよいのは、TCB で測っている時間（4ms のチャタリング待ち・5ms のタイムアウト）が無いときだけ。**あれば Idle で待つ（TCB はパワーダウンで止まる）。
  - アドレス一致（書き）: ACK して捨てる。COLL と 5ms タイムアウトでは、**先に `SCTRLB = NACK | COMPTRANS` を書いて割り込みフラグを確実に消してから** TWI を無効→有効にする（フラグの消し方としてデータシートに載っているのは SDATA へのアクセスと SCMD の書き込みだけ）。BUSERR はマスタ無効では検出されないので扱わない。
  - ADC の変換が失敗したら T=0 を返す（ホストは規則 1 の T<64 で捨てる）。
- **クリック**: PA2 の両エッジで起床 → TCB で 4ms 後に再読みして一致なら確定。
  押下: 回数 +1、プルアップを切り入力バッファも切る。以後は PIT（31.25ms）ごとに「プルアップと入力バッファを入 → 20µs → 読む → 両方切」。
  離したら回数 +1、プルアップと割り込みを戻す。
- **WDT**: 1 秒ごと（PIT 32 回）に健全性を確かめてから蹴る。確かめるもの: TWI のアドレスと制御レジスタ、ポート設定、**スティックの電源が切れていること、ADC が止まっていること、TCB の動作と「待ち中」フラグの整合**、TWI 割り込みが 1 秒に 6000 回を超えていないこと（PIT は TWI より優先度が高く、TWI の割り込み嵐だけでは WDT が効かないため）。
- 実行時にフラッシュ/EEPROM へ書かない。

## 4. キーボード側（firmware/ の Zephyr input ドライバ `hhkb,stick-pod`）
- **`CONFIG_PM_DEVICE_RUNTIME` は使わない**（入れると PM_DEVICE_SYSTEM_MANAGED が切れて ZMK がリンクできず、
  kscan の電源管理まで変わる）。代わりに**ドライバが i2c デバイスを自分で suspend/resume する**
  （`pm_device_action_run`。TWIM ドライバの PM ハンドラは resume で有効化、suspend で無効化＋sleep ピン状態）。
  TWIM は起動時に有効の状態で始まるので、**ドライバの初期化で一度 suspend する**（`-EALREADY` は成功扱い）。
  SLEEP で止める処理とポーリングは同じ mutex を取る（転送の途中で ZMK に suspend させない）。
  **ソフトオフ（電池の打ち止め）は活動イベントを出さずに全デバイスを直接 suspend する**ので、ポッドのデバイス自身も PM アクションを登録して止まる。ソフトオフでは i2c が先に止められるので「転送の途中で止めさせない」は守れない。止める処理の中でバスを resume → suspend し直して、ピンを確実に sleep 状態へ戻す。
  - 不在・固着・停止・分割リンク断では、**待ち行列を捨て、押下を出したままなら離しを出す**（ホスト側の押下状態が変わったかどうかに関係なく）。`input_report_key` が失敗したら「出したつもり」にしない。
  - 分割リンクが上がった直後は、中央機の購読が済むまで（不在周期ぶん）待ってから状態を合わせる。
- devicetree（ポッドを付ける側だけ）:
  - `&i2c1 { compatible = "nordic,nrf-twim"; status = "okay"; clock-frequency = <I2C_BITRATE_STANDARD>; pod@2a {...}; }`
  - `i2c1_default` と `i2c1_sleep` の psels を **丸ごと置換**: SCL=P0.04, SDA=P1.14, `bias-pull-up`（sleep は `low-power-enable` も）。
  - `spi2_default` と `spi2_sleep` の psels を SCK と MOSI だけに置換（P1.14 を外す）。
  - ポッドを付けない側は、既存の overlay を触らず `CONFIG_I2C` を入れない（念のため共通の dtsi で i2c1 を disabled にしておく）。
- Kconfig: ポッドを付ける側に `CONFIG_I2C=y`・`CONFIG_I2C_NRFX_TRANSFER_TIMEOUT=10`。`CONFIG_ZMK_POINTING=y` は左右とも。
- ポーリング（専用スレッド）:
  | 状態 | 周期 | 遷移 |
  |---|---|---|
  | 不在 | 2 秒 | 正常フレームで「静止」へ |
  | 静止 | 250ms（4Hz） | 不感帯の外 or 押下で「動作」へ |
  | 動作 | 10〜16ms | 中心かつ非押下が 300ms で「静止」へ |
  | 固着 | 2 秒 | **「動作」のまま連続 5 分**、傾きが不変（±3LSB）か、ボタンが押されたままのときに入る（「静止」からは入らない）。離しを出す（ゼロ移動は出さない）。押下で入ったなら規則 8 のとおりボタンを無視。傾きで入ったなら、その位置が保存済みの中心の ±0.1 以内のときだけ新しい中心にする（RAM 上。settings への保存は間引く）。外なら変化を待つ |
  - **どの状態からでも**: 失敗（規則 1・2 で捨てた、NACK、タイムアウト）が 3 回以上連続し、かつ最後の正常フレームから 150ms 以上たったら「不在」へ（規則 6 で離しを出す）。**この判定は失敗のたびに行う**（動作中は約 150ms、静止中は 750ms で不在になる）。
  - ドライバは「不在」から始める。「固着」は、傾きが変わるか、ボタンの無視が解けたら（規則 8）、**または（マスク後の）押下が立ったら**「静止」へ戻る。ただし傾きで固着した場合は、**傾きが固着時の位置から ±3LSB を超えて動くまで移動は出さない**（ボタンだけ通す。そうしないと、固着中のクリックで 5 分間また流れ出す。下書きの模擬実行 S21 で確認）。
    - **この「移動を出さない」を解くのは 2 つだけ**（2026-10-09 に実装と一緒に確定）: (1) 傾きが固着時の位置から幅を超えて動いた (2) 「静止」で中心に居るのを見た。**「不在」に入っても解かない**（不在は I2C の失敗だけでなく分割リンクの変化や停止からも来る。解くと、倒れたままのスティックが復帰のたびに 5 分流れる。模擬 S25）。
    - **未決定（利用者の判断待ち・2026-10-09）**: この「止めている」は RAM にあり、XIAO の再起動（電源の入れ直し・スリープからの起床＝System OFF は再起動）で消える。物が載って倒れたままなら、起こすたびに固着まで 5 分流れる。許すか、「起動後の最初のフレームが不感帯の外なら、止めた状態で始める」を足すか（後者は、倒したまま起動して使い始める人を 1 回妨げる）。
    - 幅は devicetree の `stuck-stable-lsb`（固着）と `centre-stable-lsb`（中心の採用）。どちらも既定 3 で、実物の読みの揺れを見て決める仮の値。
  - 遷移で言う「押下」は、**無視（マスク）を掛けた後の状態**（生のビットではない。生で見ると、押されっぱなしのボタンで 5 分ごとに 100Hz へ戻ってしまう）。
  - 「傾き不変」の基準は、動作に入ってから最後に ±3LSB を超えて動いた時点の値。傾きで固着に入るとき、ボタンが押されていれば離しを出してマスクする。
  - 中心が未保存の間は、傾きを「中心にある」とみなす（静止 ↔ 動作を動かすのはボタンだけ）。採用できないまま 1 分たったらログに出す。
  - ZMK の活動状態が SLEEP になったら止める。分割リンクが切れている間は 2 秒周期。
  - **差分ゼロのイベントは出さない**（入力イベントは ZMK の活動扱いになり、眠れなくなるため）。
- 中心: settings に保存。起動時は保存値を使い、静止中のフレームが保存値の ±0.1 以内のときだけゆっくり追従。
  **保存値が無い初回は移動を出さない。**連続 8 フレームが ±3LSB 以内でそろい、その平均の X/T・Y/T が 0.5±0.2 に入ったら、それを中心として採用・保存する（X/T は R2 やポットの値に依らず約 0.5）。**キー操作で中心を取り直す動作**も用意する（ZMK の behavior として実装し、locality は GLOBAL＝押した側に関係なく両手へ届く。名前は 15 文字以内。下書きでは Fn+Ctrl+C）。
- 変換: 不感帯 → 曲線 → 速度 → 端数持ち越しで `INPUT_REL_X/Y`。数値は devicetree の既定値として持ち、実機で詰める（下書きの仮値: 不感帯 0.040、フルスケール 0.300、最高 1200 カウント/秒、2 乗曲線、動作周期 12ms）。「±0.1」などの単位は X/T・Y/T の比。スクロールは ZMK の入力プロセッサとレイヤ。
  クリックは `INPUT_BTN_0`。
- 右に付ける場合: 右に `zmk,input-split`（`device = <&pod>`・**reg は 1**。0 は中央機で「未確定」と区別できない）、**左（中央機）にも同じ reg の `zmk,input-split` と `zmk,input-listener`**、左右とも `CONFIG_ZMK_POINTING=y`。左に付ける場合: 左のリスナーへ直結。
  付け外しは追加シールド（`hhkb_pod_right`／`hhkb_pod_remote`／`hhkb_pod_left`）として `build.yaml` で重ねる（既存の overlay は触らない）。ポッドの無い側は `CONFIG_I2C` を入れない（入ると既定の i2c1 が行ピン P0.05 を取る）。
- 分割リンクが切れたら、中央機が離しを合成するので、子機側は「出したつもりの押下」を捨てて状態を合わせ直す。
- 中心の保存値は `settings_load()`（main の中）より後で読む。ドライバ初期化の時点で「未保存」と判断しない（`h_commit` を待つ）。
- ログにブート ID・リセット要因・誤りカウンタを出す（未書き込み/リセットループのポッドを見えるようにする）。

## 5. 電力（製品仕様の電流値からの計算・未実測）
1 回の読み出し: キーボード側 1.5〜2.3µC（プルアップ 6.8kΩ を含む）、ポッド側 1.1〜1.9µC。
ポッドの床は 2〜3µA（パワーダウン 0.1µA typ＋発振/RTC/WDT 約 0.7µA＋PIT の起床 約 1µA）。

| 状態 | キーボード側の増分 | ポッド | 合計 |
|---|---|---|---|
| System OFF | 0 | 床 2〜3µA | 2〜3µA |
| 静止 4Hz | 6〜9µA | 6〜11µA（床込み） | **+12〜20µA** |
| 静止 8Hz | 12〜18µA | 11〜18µA（床込み） | +23〜37µA |
| 動作 100Hz | 0.15〜0.23mA | 0.08〜0.19mA | BLE の分割通信 0.3〜0.5mA が別に乗る（どの案でも同じ） |

右の待機 40µA に対し、静止 4Hz で +30〜50%。寿命の目安は 5.7 年 → 約 3.8〜4.4 年。System OFF 中もポッドの床 2〜3µA は流れる（基板全体の System OFF 2〜3µA と同程度）。
後からファームだけで足せる改良（裏取り済み・どちらも v1 には入れない）:

| 方式（動き出しの遅れ） | キーボード側 | ポッド（床込み） | 合計 |
|---|---|---|---|
| 素の 4Hz（250ms） | 6〜9µA | 6〜11µA | 12〜20µA |
| A: 第 2 アドレスで「変化なしなら NACK」4Hz | 3〜5µA | 5〜7µA | 8〜12µA |
| B: nRF の LPCOMP で SCL を見張る・ポッドが 8Hz で自分で測る（125ms） | 1〜3µA | 7〜12µA | 8〜15µA |

- **A は約 4 割減**（「1/3〜1/4」ではなかった。ポッドは結局測る必要があり、nRF の起床の費用も固定）。未実証の石の挙動に頼らないので、最初の改良はこちら。長さ 0 の問い合わせは nRF で動作未定義なので、「第 2 アドレスへ 11 バイト読み。NACK なら終わり、ACK ならそのまま全フレーム」にする。ポッド不在も NACK になるので、N 回に 1 回は通常の読み出しで生存確認。
- **B の利点は電力ではなく遅れ**（250ms の値段で 125ms）。成否は「System ON で LPCOMP を張ったときの電流」という、仕様書に数字の無い 1 点にかかる（System OFF の差分 0.46µA しか載っていない）。System OFF の前に確実に止める必要もある。**2 つの実測（System ON の電流・System OFF が乱れないこと）の後でだけ検討する。**
- いま用意しておくもの: 基板に「PA1 → 330Ω → SCL」のランド（部品は付けない）、フレームのバイト 1 に「A 対応」「B 対応」を示す予備ビット 2 つ。

## 6. 受け入れ試験
1. **部品を買う前に: 新しい Kconfig/devicetree で左右を CI ビルド**し、キー走査・System OFF 復帰・ソフトオフ・電池の読みが変わらないことを確かめる。
2. ポッド単体の待機電流を µA 計で測る（2.0V と 3.3V）。キット上の正体不明の 2 端子部品もここで確かめる。ヒューズを読み戻す。
3. SCL/SDA をオシロで見る（2.0V と 3.3V）: 立上り時間、引き伸ばしの長さ、両端の Low レベル。
4. 速く打鍵しながらスティックを倒し、CRC/NACK の誤り数を数える。
5. 故障を入れる: SDA を Low に固定、SCL を Low に固定、読み出し中にポッドをリセット、クリックしながらポッドをリセットループに。キーが効き続け、幻のクリックが出ないこと。
6. 静止からの遅れ（スティック/クリック → 最初の HID レポート）。静止からの速いダブルクリックが 2 回として届くこと。
7. 倒したまま起動、倒したまま挿入。クリックを 10 分押しっぱなし（固着に落ち、**押し直しが出ず、キーボードがスリープに入れる**こと）、倒したまま 6 分。
8. ポッドのレールを 2.9V → 1.8V に下げて BOD のリセットループを探す。24 時間のログでリセット 0 回を確かめる。
9. キーボードの電流: ドライバあり・ポーリング停止がドライバ無しと同じか（TWIM が本当に止まっているか）。静止 4Hz / 8Hz / ポッド無しの比較。System OFF とソフトオフの電流。電池が減った状態での活線挿抜。
10. BLE のパケット誤り率を、100Hz ポーリング中と停止中で比べる。
11. ボタンを押したまま（静止中とドラッグ中の両方で）ポッドを抜く → 「離し」が届くこと。5 回以上クリックした後、静止中に 1 秒以内で挿し直す → 幻のクリックが出ないこと。
12. 中心が未保存の初回起動。フルに倒したまま 6 分 → 離しても流れないこと。キー操作での中心の取り直しが効くこと。

## 7. 残るリスク
- **2 つ目のファームが最大のリスク**（TWI の終端手順、PIT/RTC の errata、スリープ中に使えるタイマが 1 本）。CI に avr-gcc のビルドとプロトコルの単体試験を足すまでは CI の外。
- 静止からの遅れ（最大 250ms）は使い心地の費用。4Hz で不満なら 8Hz（電力 2 倍）か注意線。
- クロストークの余裕は推定。試験 3・4 で確かめる。
- スティックの抵抗値・可動範囲・接点抵抗は未実測。10bit のうち実際に使える段数は数百の見込み。
- ドライバによる i2c の手動 suspend/resume はソースを読んだだけ。ビルドと試験 9 で確かめる。
- 右は #55（PMW3610）と同じピンを使うので差し替え。
- **傾きの固着判定（±3LSB 不変が 5 分）は暫定。**倒したままの手が 3LSB を超えて揺れると固着に落ちず、キーボードを起こし続ける（下書きの模擬実行で 35 分継続）。ADC の雑音を実測してから、幅のある窓で判定するかを決める。
- 右は左と独立に眠る。左だけを 30 分打つと右は System OFF に入り、スティックでは起こせない（右のキーを押せば起きる）。
- リポジトリの検査（`tools/check_zmk_config.py` ほか）は、追加シールドを重ねた `build.yaml` に合わせて直す必要がある。
