## 右手の帯

### 作る順番
1. ユニバーサル基板（秋月 g112019）を 13×7 穴に切る
2. **被覆のジャンパ線を先に付ける**: 穴 (2,1) → (2,11)。部品面を通す（あとでキットの下になる）
3. 抵抗とコンデンサを挿してはんだ付けする。抵抗は折って立てる（Rs_SCL だけ寝かせる）
4. はんだ面で、図の色帯のとおりに隣の穴どうしをブリッジする
5. キットにマイコンのプログラムを書き込む（**載せる前に**。あとからは上からクリップで）
6. キットを、付属のピンヘッダで列 1〜10・行 0 と行 3 に載せる
7. 線 13 本を挿す（XIAO へ 4 本、スティックへ 9 本＝足 1 本につき 1 本）。順番と長さは `../BUILD.md` の 2-3・2-4

### 気をつける所
- **列 0 と列 1 の間は、行 2〜6 の 5 か所すべてで GND と VDD が隣り合う**（(2,0)-(2,1)・(3,0)-(3,1)・(4,0)-(4,1)・(5,0)-(5,1)・(6,0)-(6,1)）。はんだを流さない。
  行 2・3 はキットを載せると見えなくなるので、**載せる前にテスターで VDD–GND が短絡していないことを確かめる**
- 10µF（g116018）は足の間隔が 5mm。足を内側へ曲げて 2.54mm の穴に挿す。板の端の行 6 に置く（胴が板から 0.2mm ほどはみ出す）
- 33Ω は**小型の品（g108517・胴 3.3mm）**を使う。普通の 1/4W（胴 6.3mm）は立てると背が高すぎる
- 使っていないピンの隣の穴 (4,2)(4,8) にブリッジを作らない
- キットのピンの並びは商品写真のシルクから読んだ。**届いたらシルクと図を見比べる**（VDD と GND が同じ端で向かい合う）

### 保護の抵抗あり／なしを両方試す
抵抗 5 本（Rw_X・Rw_Y・Rk の 1kΩ、Rs_SDA・Rs_SCL の 330Ω）は、**同じ穴に線（抵抗の切った足）を挿せば「なし」になる。**
帯も配線も同じ。

### 前の仕様（K 案 v7）から変えた所（**ファームの下書きも直した**: `firmware/pod/pod.c`（リポジトリの直下から）・コンパイル 0 警告・2,234 バイト・実機未実行）

| 何を | 前 | いま | 理由 |
|---|---|---|---|
| 抵抗の上端の電圧を測るピン | PA4（1kΩ 経由） | **PB5 そのもの**（電源を出しているピンを測る） | 抵抗 1 本と線 1 本が減る。10kΩ のスティックでは直列抵抗が要らない（電流 0.58mA） |
| Y を測るピン | PA6 | PA7 | 下の行のためにあける |
| スイッチのピン | PA2 | **PA6** | キットの VDD 側の列に寄せる。PA6 も「完全非同期ピン」（データシート） |
| 100pF の行き先 | GND | **VDD** | 帯の奥の端に GND が来ない。雑音よけとしては同じ（VDD は 10µF で GND に落ちている） |

受動部品は 13 個 → **12 個**。

## 左手の帯

抵抗 100kΩ×2 とダイオード BAT43 を載せる。置き場所は主基板の下・底板の上で、エンコーダの左 約 20mm（机の座標 (38.0, 37.8)）。
部品を高さ 6mm の箱と見て実形状に当て、食い込み 0・上の空き 2.6mm。絵は `../images/left_r_inside.jpg`・`left_r_route.jpg`（元の .blend は git の外 `build/joystick/`）。
（子基板の真下は上の空きが 0.6mm しか無く、やめた）

- ダイオードは**帯の印（カソード）を「XIAO D5 へ行く線」の側**へ（帯の穴の列 5 の側。キーの行列の「列 5」とは別の話）
- コンデンサ 2 個（Ca・Cb）は**最初は付けない**。止めたまま打鍵してスリープに入れないときだけ 1nF 前後を足す（品番は未選定）
- 抵抗を 470kΩ や 1MΩ に替えて試すときも同じ穴
- エンコーダのスイッチの端子 4 は、帯を通さず「5」のキーのソケットの列側のパッドへ直接つなぐ
- エンコーダの LED の端子（2・3）は使わない

## マイコンへの書き込み（部品が届いたら）

`pod_incase.hex`（6.3KB・2026-10-07 にビルド）を書く。**キットを帯に載せる前に書く。**道具の入れ方とオプションは実際に入れて確かめた（pymcuprog 3.19.4）。書き込みそのものは未実行。

1. つなぐ: 変換器の RX → キットの RST（シルクは「RST」。配置図の PA0 と同じピン）、変換器の TX → BAT43 → RX（帯の印を TX 側へ）、GND どうし、変換器の電源 → キットの VDD
2. 道具を入れる: `python3 -m pip install pymcuprog`
3. 応答を見る: `pymcuprog ping -t uart -u /dev/tty.usbserial-XXXX -d attiny1616 -c 57600`（ID が返れば配線は合っている）
4. プログラムを書く: `pymcuprog write -t uart -u /dev/tty.usbserial-XXXX -d attiny1616 -c 57600 -f pod_incase.hex --erase --verify`
5. ヒューズを 3 つだけ書く（**SYSCFG0 は書かない**。間違えると 12V の書き込み器が無いと戻せない）:
   - `pymcuprog write -t uart -u … -d attiny1616 -m fuses -o 0 -l 0x0B`（番犬タイマ 8 秒）
   - `pymcuprog write -t uart -u … -d attiny1616 -m fuses -o 1 -l 0x08`（電圧低下の検出 1.8V）
   - `pymcuprog write -t uart -u … -d attiny1616 -m fuses -o 2 -l 0x02`（発振器 20MHz）
6. 読み戻す: `pymcuprog read -t uart -u … -d attiny1616 -m fuses`

### 帯に載せた後で書き直すとき（XIAO とつながったまま）
実機ではまだ一度も動かしていないので、書き直しは起きる前提でいる。
1. キーボードは **USB でつないで給電する**（電池だとレールが 2.0〜2.9V で、変換器の信号の方が高くなる）
2. 変換器は **3.3V の品**を使い、**電源の線はつながない**。つなぐのは GND と UPDI（キットの RST）の 2 本だけ
3. キットの上面のピンにクリップかピンを当てる。コマンドは上と同じ
5V の変換器しか無いときは、キットを外して書く。
