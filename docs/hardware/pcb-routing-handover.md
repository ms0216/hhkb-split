## 役割分担

```
tools/gen_pcb.py     配置・ネット・ゾーン・設計規則（配線は持たない）
      ↓  pcb/unrouted/hhkb_split_{half}.kicad_pcb
tools/autoroute.py   DSN → Freerouting → SES → ゾーン塗り直し
      ↓  pcb/hhkb_split_{half}.kicad_pcb
```

例外は**決まりきった局所配線**の 2 つだけ。どちらも経路に選択の余地が無く、
自動配線器に任せると却って悪くなる。DSN からはネットごと外し、配線材は
`(type protect)` で「避けるべき障害物」として渡す。

| | |
|---|---|
| スイッチ → ダイオード | `gen_pcb.prewire_switch_diode`。裏面の L 字 2 本。ビア 0 |
| GND のパッド → ベタ | `tools/gnd_fanout.py`。パッドの長軸方向へビア 1 個 |

## 手書きルータをやめた理由

**「残りは引き回しの微調整」という診断が誤っていた。**

- `ROW4` と `ROW1` のような**任意のネット対**が短絡していた。これは経路の
  良し悪しではなく、**自分が引いた線を見ていない**ことの帰結。衝突判定を
  持つルータは構造的に出せない
- リップアップも大域的なコスト関数も無いので収束しない。25→34、24→144、
  23→36 と何度も戻した
- `SOIC-16` はコートヤード 10.49mm で、帯 9.25mm に**そもそも入らなかった**。
  位置の微調整（`-1.8`）は、どちら側にはみ出すかを選んでいただけ

設計: [2026-08-08-pcb-autoroute-design.md](../superpowers/specs/2026-08-08-pcb-autoroute-design.md)

## Freerouting を通すために要った 3 つ（全部つまずいた）

### 1. `J_DB`（FFC）がダイオード列に載っていた

上段キーのダイオードは帯へ **1.75mm 食い込み、19.05mm ピッチ**で並ぶ。
帯の部品で `J_DB` だけ背が高く（7.9mm）、その x がちょうど `D3` の列だった。
短絡・コートヤード重なり・`ROW0` の未配線は**全部これ**。

→ `J_DB` とその玉突きで `C_BULK` / `C_MCU`（のち `C_RAIL` に改名。
**2026-08-14 に削除。open-gaps #40**） をダイオードの隙間へ移した。

**帯に部品を足すときは、ダイオード列の x を避けること。**

### 2. GND パッドがベタに届かない

GND ベタは `In1.Cu` の 1 層だけ、GND パッドは全部 `B.Cu` の SMD。
間のビアを Freerouting 任せにすると、混んだ区画で失敗する
（対応する SMD ピンの **42% しかファンアウトできなかった**）。

→ `tools/gnd_fanout.py` が配置段階に決定的に立てる。向きは**パッドの長軸**
（支配軸でやると FFC の横並びパッドで隣に刺さる。実際にやった）。

**`ImportSpecctraSES` は既存の配線を全部作り直すので、取り込みのたびに
自分で引いたものが消える**（実測: GND のビア 7 個 → 0 個）。
`autoroute.py` が上の 2 つとも立て直す。

### 3. DSN に GND を残すと Freerouting が NPE で落ちる

ピンだけ消してネット定義を残す、のような中途半端なやり方をすると
`NullPointerException` で GUI ごと落ちる。ネット定義・クラスの一覧・
plane 宣言を**まとめて**消すこと（`_strip_prewired`）。

ファンアウトの配線材は `(type protect)` に変えて、ネットを持たない
固定障害物として渡す。**消すと避けてくれない。**

## 配線の質（手書き → Freerouting）

⚠️ **この表は 2026-08-08 頃、基板がまだ 4 層だった時期の実測。**
2 層化・GND ビア増量（指摘 4/5）後の値ではない。**現在のビア数は
GND だけで左 732 個・右 913 個**（84df0cb・86e0101 の実測）で、
この表の数値とは前提が違う。層構成の推移を示す歴史的記録として残す。

| | 左 | 右 |
|---|---|---|
| DRC 違反 | 33 → **0** | 32 → **0** |
| 総長 | 1817 → **1538mm** | 2290 → **1902mm** |
| ビア | 58 → **40** | 68 → **51** |
| 遠回りの最大 | 2.3 → **1.6** | 2.3 → **1.6** |
| `In1.Cu` の配線 | 0 → 0 | 0 → 0 |
| GND の島 | 1 → 1 | 1 → 1 |

**ビアは手書きより減った。**一度は左 68・右 111 まで増えたが、原因は
`SW*_D`（スイッチ → ダイオード）だった。数 mm の接続のために自動配線器が
内層へ往復し、左 30 個・右 62 個をそこに使っていた。**この配線は経路に

両面（F.Cu・B.Cu）で受ける形に変わっている。

## 配線の思想（B.Cu が主・F.Cu は橋）

**2026-08-15・利用者の指摘**「可能な限り B.Cu で配線し、交差するところだけ
ビアで最短だけ F.Cu に潜ってすり抜ける、という形になっているはずだが、
守られていない箇所が至る所にある」。

**実測したら本当だった。** F.Cu の連結成分ごとに長さを測ると、
「短い橋」ではなく**端から端まで F.Cu を走る本線**が並んでいた
（左 COL0 が 78mm、右 CS が 84mm、右 V3V3 が 93mm）。
両端ビア間の直線距離との比（detour）が 1.0 前後、つまり
**迂回している橋ではなく、F.Cu に移住した本線**。

→ `autoroute.py` の `_autoroute_settings` が DSN にコストを入れる。

| | F.Cu | 成分数 | ≤5mm の橋 | >10mm | ビア |
|---|---|---|---|---|---|
| 左 前 | 531mm (22.3%) | 19 | 6 | 12 | 1028 |
| 左 後 | **245mm (10.5%)** | 35 | **22** | **7** | 1008 |
| 右 前 | 804mm (25.1%) | 28 | 8 | 19 | 1281 |
| 右 後 | **391mm (12.3%)** | 49 | **29** | **10** | 1269 |

**F.Cu の銅が半分以下になり、本数は増えた**——長い本線が短い橋に
置き換わったということ。**ビアはむしろ減っている**（左 1028 → 1008）。
DRC は 3 枚とも**違反 0・未配線 0**。

### 効くのは `via_costs`。層のコストではない

層コスト比を 5 / 20 / 100 と振っても F.Cu は 22.1% で**全く動かない**。
動くのは `via_costs`——**B.Cu に留まるにはビアを惜しまず打つ必要がある**
ので、ビアが高いと長い F.Cu の迂回を選ぶ。

### ⚠️ `via_costs` を 0 にしてはいけない（F.Cu が増える）

2026-08-15・利用者の問い「ビアコストは 0 とか可能な限り最小にできないのか」。
**実測したら逆効果だった。**

| via_costs | 左 F.Cu | 右 F.Cu | 右ビア |
|---|---|---|---|
| 30 | 22.1% | — | — |
| 5 | 15.0% | 19.5% | 90 |
| **2** | **14.6%** | **16.8%** | 103 |
| 0 | 16.8% | **24.8%** | 119 |

0 では右が 24.8%——**何もしない状態（25.1%）へほぼ逆戻り**する。
ビアは 119 個に増えているのに F.Cu も増える、両方損の状態。

**ビアが無料だと「橋を短くする理由」が消えるため。**3 回潜って戻る経路も
1 回で済む経路も同じ値段なので、ルータは経済性を考えるのをやめてふらつく。

> **「短い F.Cu は歓迎、長い F.Cu は嫌う」を実現しているのは、
> ビアにわずかな値段が付いていること。**橋が短いほどビア 2 個分の元が
> 取れるので短い橋が勝ち、長い F.Cu は「そんなに走るなら潜り直せ」と負ける。

なお **Freerouting のコスト関数では「その連結成分の全長」のような大域的な量は
書けない**（`AutorouteSettings` にあるのは via / trace / ripup のみ。
逆アセンブルで確認）。`via_costs` がその代理として働いている。

値は単調ではない（4 → 5 → 6 が行ったり来たりする）。コストを変えると探索
経路ごと変わるため。**1〜2 ポイントの差で良否を決めないこと。**

### クリアランスの余裕を 20 → 30µm に上げた

B.Cu が密になったぶん、Freerouting の丸め不足が顕在化した
（左 0.1992mm・右 0.1967mm ＜ 規則 0.2000mm）。
20µm では違反 左1/右2、30µm で **違反 0/0/0・未配線 0/0/0**。

### ⚠️ 2026-08-14 の「autoroute_settings を足すな」は誤りだった

当時「左が未配線 1 → 66 本に激増、値を変えても同じなので**ブロックの
存在そのものが悪い**」と結論して禁止していた。**そうではない。**

1. **挿入位置が `parser` スコープの中だった。**`"\n  )\n"` を正規表現で
   探すと structure ではなく **parser の閉じ括弧に先に当たる**。
   未知のスコープは黙って捨てられるので、**値を変えても何も起きない。**
   「値ではなくブロックの存在が効く」の正体はこれ
2. **層ごとのコストは `(layer_rule <層名> ...)` の中**にある。当時は
   global の `via_costs` しか書いておらず、**層コストは一度も
   設定されていなかった**

構文は Freerouting 2.3.0 の `io/specctra/parser/AutorouteSettings.class` を
逆アセンブルして確認した（推測ではない）。`_autoroute_settings` は
**入れたあとに括弧を数え直して structure の内側かを検査する**。
故意に parser の中へ入れて、検査が捕まえることを確認済み。

**教訓: 「効かない」と「間違った場所に書いた」は区別がつかない。**
設定を足したら、**効いたかどうかを数字で見る**（CLAUDE.md の作法 5）。

### 途中で見つけた別の欠陥（**まだ直っていない。手を付けていない**）

**`gnd_fanout` のスタブは `B.Cu` 決め打ちで引かれているが、SMD の GND
パッドは左右 11 個とも F.Cu にある。**つまり**スタブはパッドに触れて
いない**（空中から始まってビアに刺さるだけ）。それでも繋がって見えて
いたのは F.Cu のベタがパッドに被っていたからで、**繋いでいたのは
スタブではなくベタだった。**

途中の設定（`via_costs=5` + 余裕 20µm）で B.Cu が密になったとき、
ベタが割れて右の `U1` パッド 13（74LVC595 の GND）が孤立し、露見した。
ビアは 1.54mm 離れた位置にあり、間を繋ぐ銅がどこにも無かった。

**最終的な設定（`via_costs=2` + 余裕 30µm）では顕在化していない**
（違反 0・未配線 0）。**が、直ったわけではない。**ベタの形が変われば
また出る。**潜在的なままなので、いずれ直すこと。**

直そうとして失敗した記録（同じ道を 2 回通らないため）:

| 試したこと | 結果 |
|---|---|
| スタブをパッドの層に合わせる | 右が**違反 0 → 17・未配線 2 → 3** に悪化。F.Cu のスタブが F.Cu の配線と当たる（`_candidates` / `_blocked` はパッドしか見ていない） |
| 同上＋`gen_pcb` から引き直して protect で渡す | 違反 1 まで戻せたが、**孤立が `U1` から `C_U1` へ移っただけ** |
| SMD はパッドの真上にビアを置く | **置けない。**必要な直径 1.7mm に対し TSSOP のパッド幅は 0.4mm・ピッチ 0.65mm。`_blocked` が正しく拒否する |

⚠️ **`spots()` は配線を見てはいけない**という制約がある（配線の前後で
同じ位置を返す必要がある。関数の docstring 参照）。
**素直に直せないのはこのため。**置き場所の探索を層ごとに分けるところから
設計し直す必要がある。

## やってはいけないこと（実際に悪化させた）

1. **接頭辞でフットプリントを走査する。**`D`／`SW`／`SW_` で拾うと
   電源部の `D_PWR`／`SW_PWR`／スライドスイッチと、61 個のダイオード・
   スイッチを巻き込む。**同じ事故が 4 回起きている。**
   `re.fullmatch(r"D\d+")` のように絞る
2. **原因を特定せずにパラメータを振る。**必ず
   `kicad-cli pcb drc --format json` で「どのネットとどのネットが、
   どこで」当たっているかを見てから動かす
3. **正規表現でコードを書き換えるとき、置換後を確認しない**

- **DRC の件数は実行ごとに数件ゆらぐ**（ゾーンの塗りとの兼ね合い）。
