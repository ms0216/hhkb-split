## 分かっている原因と、試して**失敗した**手

### ★ U1（SOIC-16）が帯からはみ出している

帯は 9.25mm、SOIC-16 は既定で**縦 10.4mm**。行のバス（キー中心から
KiCad で +3.65mm）に重なる。

**`fp.SetOrientationDegrees(90)` で寝かせるのを試したが、違反が 24 → 144 に
悪化した。** 回転するとパッドの並びが変わり、`_route_electronics` の
レーン割り当て（x 順を前提）が崩れるため。回転させるなら、
ピンの並びに合わせた配置の見直しとセットで行うこと。

**代わりに位置で逃がした。**`PLACE` の 3 つ目の要素が帯の中での y の
微調整。-1.8 / -2.6 / -3.4 を実測して -1.8 を採った。

**注意: DRC の件数は実行ごとに数件ゆらぐ**（ゾーンの塗りとの兼ね合い）。
1〜2 件の差で良否を判断しないこと。

**別解**: 帯の中心を行のバスから離す方向へ数 mm ずらす。ただし
`BAND_Y` のずらし方向は**符号を間違えると大幅に悪化する**
（−2.3 で 96/130、+2.3 で 101/124 になった実験がある。
現在の値 `_SOCK_MID = +2.3` が最良）。

### ✅ 行のビアが表面の列バスに乗る — 解決済み

`_fcu_verticals` で表面の縦配線を拾い、`_clear_x` で避けるようにした。
列と行の短絡が 11 → 2 件になった。

### ★ V3V3 と VBATT_SENSE

FFC の 0.5mm ピッチから扇状に広げる部分。レーン（`_link` の `lane`）と
引き出し距離（`d`）の両方をずらしてあるが、まだ寄っている。

## 効いた手（同じ考え方が使える）

| | 効果 |
|---|---|
| **コネクタのピン順と部品の並びを揃える** | 子基板 33→3、本体 右 57→37 |
| **GND はベタで受ける**（配線しない） | 扇状に広げる本数が減り、順序を素直にできる |
| **穴避け（`_clear_x`）を内層にも適用** | 行 5 本が通り、未配線 5→0 |
| **通路・レーン・引き出し距離を「測って選ぶ」** | keep は 1.0/1.6/2.0/2.5 を実測して 2.0 を採用 |

---

## やってはいけないこと（実際に悪化させた）

1. **原因を特定せずにパラメータを振る。** レーンの取り方を推測で変えて
   25 → 34 に増やした。必ず `kicad-cli pcb drc --format json` で
   「どのネットとどのネットが、どこで」当たっているかを見てから動かす
2. **正規表現でコードを書き換えるとき、置換後を確認しない。**
   `BAND_Y` の置換を誤って 96/130 まで悪化させた
3. **接頭辞でフットプリントを走査する。** `D`／`SW`／`SW_` で拾うと
   電源部の `D_PWR`／`SW_PWR`／スライドスイッチを巻き込む。
   **今日 3 回同じことが起きた。** `re.fullmatch(r"D\d+")` のように絞る

---

## 残る手順

1. 上記 3 つの原因を潰して DRC 0 にする
2. `tools/test_pcb.py` の `WIP_BOARDS` を空にする
   （`test_the_unfinished_boards_are_declared` が「綺麗になったのに
   残っている」状態を検出するので、忘れることはない）
3. ガーバー・BOM・CPL を出す（`kicad-cli pcb export gerbers` ほか）
4. [open-gaps](open-gaps.md) の #16 を閉じる
