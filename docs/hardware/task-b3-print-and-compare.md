# Task B3 — 3Dプリントして実機と比べる

**部品の到着を待たずにできる。** そして**私にはできない検証**でもある。

---

## 1. なぜやるか

ケースの寸法は、実機を分解せず公開情報だけから導いた。数値としては
[dimensions.md](dimensions.md) に根拠を残してあるが、**手で触った感触は
数値に出ない**。

とくに次の 3 つは、実物を並べないと判断できない。

| 確認したいこと | 数値では分からない理由 |
|---|---|
| **手前端の高さ 17.5mm** | 手首が当たる高さ。1mm 違うと体感が変わる |
| **打鍵面の傾斜 7.3°** | 実機と並べて横から見れば一目で分かる |
| **各段のキートップ高さ** | 指を置いたときの段差の感じ |

寸法の出どころは実測 17mm と別レビュー約 18mm の中間を採るなど、
**幅のある推定が混ざっている**。実物で詰められるならその方がよい。

---

## 2. 何を印刷するか

すべて `build/` にある。OrcaSlicer での確認は済んでいる（18/18 スライス成功）。

### まず刷るもの（合計 40 分ほど）

| ファイル | 時間 | 何を見るか |
|---|---|---|
| `front_edge_8deg.stl` | 12 分 | **手前端の断面**。3 つ刷って実機と比べる |
| `front_edge_12deg.stl` | 12 分 | 同上 |
| `front_edge_16deg.stl` | 12 分 | 同上 |
| `height_gauge.stl` | 26 分 | **各段のキートップ高さ**を測る治具 |

**手前端の断面が最優先。** 実機の手前は単純な直線ではなく、指摘を受けて
造形を直した経緯がある。3 つの角度を並べて実機に当てれば、どれが近いか
（あるいはどれも違うか）がすぐ分かる。

### 次に刷るもの（3 時間半ほど）

| ファイル | 時間 | 何を見るか |
|---|---|---|
| `case_left.stl` | 1h39m | 全体の姿・傾斜・手前端の高さ |
| `battery_lid_left.stl` | 6 分 | 蓋がレールに収まるか |
| `tilt_foot_0deg_left.stl` | 4 分 | 脚が穴に入るか |
| `tilt_foot_3deg_left.stl` | 6 分 | 3° の傾きが出るか |
| `tilt_foot_6deg_left.stl` | 8 分 | 6° の傾きが出るか |

**ケースは寸法が変わった直後なので、刷るなら今の版で。**
プレートの奥行を実機どおり 108mm にした変更が入っている。

## 3. 実機と比べる

### 3-1. 手前端（最優先）

実機の手前端に、印刷した 3 つの断面を順に当てる。

| | 実測 |
|---|---|
| どれが最も近いか（8° / 12° / 16°） | |
| 高さは合っているか（設計 17.5mm） | |
| 断面の形は合っているか（直線か、丸みがあるか） | |

**どれも違う場合は、その旨と「どう違うか」を教えてほしい。**
「もっと丸い」「もっと立っている」程度で構わない。

### 3-2. 高さゲージ

`height_gauge.stl` を実機のキーの横に立て、各段のキートップと比べる。

| 段 | 設計値 | 実機と比べて |
|---|---|---|
| 最下段（Space の段） | 26.7mm | |
| 4 段目（Z X C） | 29.2mm | |
| ホーム段（A S D） | 31.6mm | |
| 3 段目（Q W E） | 35.6mm | |
| 数字段 | 40.0mm | |

**ホーム段 31.6mm が最重要。** 指が最も長くいる高さ。

### 3-3. ケース全体

| | 実測 |
|---|---|
| 横から見た傾斜が実機と揃うか | |
| 手前端の高さが同じか | |
| 奥行 108mm が実機の本体と一致するか | |
| チルト脚を挿して 3° / 6° になるか | |

## 4. 印刷の設定

`tools/slice_check.py` が使うのと同じ条件で確認してある。

- プリンタ: Creality K1 Max
- フィラメント: PLA
- 層厚: 0.2mm
- **サポート不要**（全部品でサポートが要る面 0%）

ケースは底面を下にして置く。ベッドとの接地面積は確保済み。

---

## 5. 結果の扱い

**寸法が違っていたら直す。** 実機に合わせるのが基本方針なので、
設計値の方を動かす。

ただし [tools/test_invariants.py](../../tools/test_invariants.py) が
これらの値を固定しているので、**根拠（実測値）を
[dimensions.md](dimensions.md) に書いてからテストを更新する**。
根拠なしに緩めない。

---

## 6. これは私にはできない

CAD の生成物はメッシュの健全性もスライスの可否も機械で検証しているが、
**実機と並べて「近いか」を判断することはできない**。ここだけは
実物を持っている人にしか閉じられない。
