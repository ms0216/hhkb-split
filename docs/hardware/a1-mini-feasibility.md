# Bambu Lab A1 mini で刷れるかの検討（2026-08-23）

プリンタが K1 Max（300×300×300）から A1 mini（180×180×180）に変わる
可能性が高い、との利用者の連絡（2026-08-23）を受けた実測ベースの検討。
**印刷容易性・組み立て容易性も評価軸に含める**（同日の追加指示）。

## 結論（先に）

| 部品 | 幅×奥行 (mm) | A1 mini | 根拠 |
|---|---|---|---|
| case_left / topcase_left | 146.4×125.1 / ×107.1 | **刷れる** | 実スライスで確認（下） |
| plate_left ほか小物全部 | ≤143×104.4 | **刷れる** | 同上 |
| **plate_right** | **176.3×104.4** | **限界圏**（手動配置のみ） | 余裕 1.85mm/片側。自動配置は落ちる |
| **case_right / topcase_right** | **179.7×125.1** | **実質刷れない** | 余裕 0.15mm/片側。スカートもブリムも不可 |

**右の大物 3 点だけが問題。**選択肢は下の「打ち手」。

## 測った事実（すべて機械検証・2026-08-23）

1. **STL の外形**: 全 23 部品の bbox をバイナリ STL から直接読んだ。
   180mm を超える部品は無いが、case_right / topcase_right が 179.7mm。
2. **プロファイル**: OrcaSlicer 同梱の A1 mini 機体定義は
   `printable_area 180×180`・`bed_exclude_area 無し`・高さ 180。
   （Bambu 公式 wiki の「切断レバー用の除外」は A1 mini の
   プロファイルには入っていない。）
3. **実スライス**（OrcaSlicer CLI・A1 mini 0.4 / Generic PLA / 0.20mm）:
   - 大きさを振った箱で合否の地図を取った。**CLI は必ず自動配置を通り、
     その内寸は `bed_shrink 3.4mm ＋ brim_skirt_distance 2.4mm` で
     実効 約168.4mm 角**（斜め置きは可。176.3×60 は 45° 置きで通る）。
   - つまり **CLI 検査（slice_check --printer a1mini）で右の大物は NG になる**。
     GUI で手で置けば 180 ぎりぎりまで置けるが、それでも
     case_right は 0.15mm/片側しか残らない。
4. **位置依存の禁止領域は無い**: 20×20 の箱をベッドの四隅・四辺に
   置いても全部通る。落ちるのは大きさだけが理由。

## ✅ 実測（2026-08-24）: 幅 177.6mm は A1 mini で刷れる

試し板 `bed_edge_strip_177p6.stl`（177.6×10×1.0・スカート/ブリム無し・端置き）を
**実機で印刷し、欠け・剥がれなく完走**。全長は定規（分解能 1mm）で
177〜178mm の中間＝設計値と一致。位置決め誤差・初層の潰れは
余裕 1.2mm/片側の中に収まっている。

これで**打ち手 D が立つ**:

### 打ち手 D: 右の分割面の余白を 4.125 → 2.0mm に詰める（幅 179.7 → 177.6）

- **外側の縁（実機再現の 4.125mm）は触らない。**削るのは分割面
  ——実機に存在しない面——だけなので、基本方針と衝突しない
- 印刷容易性: A1 mini に**分割せず**入る（実測済み）。ただし常に手動で
  端置き・スカート無し
- 組み立て容易性: **変化なし**（部品数・接合部が増えない。B より圧倒的に楽）
- 必要な作業: `PLATE_MARGIN_X` を左右非対称にする設計変更（プレート・
  ケース・上ケース・基板の 4 者が同じ関数を通るので影響は interface.py に
  集中）＋ ネジボス・干渉・挿入経路の再検査 ＋ 左も同様に詰めるか決める
- 残 risk: ベゼル側壁が分割面だけ 1.6mm になり、見た目の左右非対称が
  分割面の縁に出る（幅 2.1mm ぶん）

## 打ち手 D の確定版候補（2026-08-24 深夜・実機の隙間を実測して更新）

追加の実測と制約の解き直しで、D は次の 2 候補に絞れた:

**前提となる実測・発見:**
- 実機のキャップ↔ベゼルの見える隙間は **1.0〜1.5mm**（利用者実測）。
  いまの設計 1.825mm は実機より広い——詰める余地はむしろ実機再現に近づく
- **基板は凍結（手配線・DRC 0）なので外形を 1mm も変えられない。**
  ケース内面と基板縁のクリアランス（現状 0.6mm）が幅詰めの隠れた上限
- 余白の恒等式（片側）: `余白 = 開口の隙間 + ベゼル壁 + 押さえ`。
  壁を薄くしても幅は縮まず**押さえが増える**（プレート縁 = 外面 − 壁 のため）

| | 候補 1（**推奨**・幅 178.5） | 候補 2（幅 177.7） |
|---|---|---|
| 開口の隙間 | 1.5 → 0.9（見え 1.225・実機範囲内） | 0.9 または 0.675 |
| ベゼル壁 | 1.6 → 1.2（3 周） | 1.2 |
| 押さえ | 1.025 → **1.43（増）** | 1.02〜1.25 |
| ケース側壁 | 2.4 → 2.0（5 周） | 2.4 → **1.6（4 周）** |
| 基板クリアランス | 0.40mm | 0.40mm |
| ベッド実証 | **未**（余裕 0.75/片側・試し板印刷中） | ✅ 済（177.6 実測） |

候補 1 の試し板（`bed_edge_strip_178p5.stl`）が通れば候補 1 で確定。
落ちれば候補 2（側壁 1.6 の強度低下を受け入れる）か A/B へ。

## ⚠️ 候補 3 の試験実装で見つかった課題（2026-08-24 朝・幅詰め全案に共通）

候補 3 を実際に実装して検査を通した（その後**全部巻き戻した**。板は凍結状態のまま）:

- ケース・プレート・幾何検査は成立（102 件緑・箱モード干渉なし）
- **子基板と J_DB の位置はケース幅に連動する**（「内側の壁ぎわに寄せる」
  設計なので、壁が 1mm 内側へ来ると子基板も 1mm 逃げるしかない）
- その結果、**右基板が 未配線 9 / 違反 40**——短絡はすべて J_DB
  ファンアウトの帯（ROW どうし・CS↔V3V3・SPI 系）。**利用者の手配線の
  下からコネクタが約 1mm ずれた**形。左は J_DB 周りが生成器の領域なので
  0/0 で通った
- ⚠️ **これは候補 1/2 でも同じ**（基板外形を触らなくても、ケース幅が
  縮めば子基板は物理的に動く）

**幅詰め（D 系）を採る場合の共通コスト**: 右基板の J_DB 周りの手配線
（9 ネット）を、約 1mm ずれた新しい J_DB 位置へ利用者が引き直す。
引き直したら `export_matrix_routing.py` で写して完成。
やらないなら打ち手 A（右だけ K1 Max）/ B（2 分割）に戻る。**利用者の判断待ち。**

（試験実装の道具は残した: `finalize_pcb.py --src unrouted` — 外形を変えた
とき、利用者の板 `matrix_only` を上書きせずに gen_pcb の再現板から
本番を作るための入力切り替え）

**A1 mini は同じ部品で 2.4〜4.3 倍かかる**（スライサーの推定値。
K1 Max の Creality 製プロファイルが速度側に振ってある差が大きい）:

| 部品 | K1 Max | A1 mini | 倍率 |
|---|---|---|---|
| case_left | 1h 52m | 8h 07m | 4.3× |
| topcase_left | 28m | 1h 45m | 3.7× |
| plate_left | 42m | 2h 03m | 2.9× |
| rf_spacer_pair | 7m 30s | 17m 48s | 2.4× |

⚠️ 最初の計測はフィラメントに「0.2 nozzle」用が選ばれ（プロファイル名の
辞書順の罠・slice_check の pick を完全一致優先に修正済み）、さらに 2 割
遅い値が出ていた。上の表は修正後。

## 印刷容易性・組み立て容易性の比較

### 打ち手 A: 右の大物 3 点だけ K1 Max で刷る（他は A1 mini）

- 印刷容易性: **現状のまま**。実績のあるスライス検査も K1 のまま効く
- 組み立て容易性: **変化なし**（部品数・接合部が増えない）
- 前提: K1 Max が使える環境が残ること。**プリンタが完全に入れ替わるなら不成立**

### 打ち手 B: 右のケース・上ケース・プレートを 2 分割し、接合する

- 印刷容易性: **上がる**（各片 ~90×125。反りにくく、ベッド中央に置ける）
- 組み立て容易性: **下がる**。接合部（ダボ＋M2 か、あり継ぎ＋接着）が
  右だけで 3 部品×1 継ぎ増える。**プレートの分割はキー保持の剛性に直結**
  するので、分割線はスイッチ穴を避けて縦に 1 本、裏にリブを足す設計が要る
- 品質: 継ぎ目が外観に出る（上ケースは目立つ）。**実機再現の観点で減点**
- 検査: `gen_assembly` の干渉・挿入経路検査に接合部を足す必要

#### 打ち手 B の分割線は「直線では引けない」（2026-08-24 に計算）

右プレートはキー開口（14mm 角・ピッチ 19.05）が段ごとに互い違いで、
**全段を通る縦の回廊が存在しない**（開口の x 帯が −83.2〜83.2 で連続）。
分割するなら**段ごとのキー境界（隙間 5.05mm）を縫う階段状**になる:

| 段（y） | 中央付近で使える境界 x |
|---|---|
| +38.10 | −9.53 または +9.53 |
| +19.05 | 0.00 |
| 0.00 | +4.76（または −14.29） |
| −19.05 | −4.76 |
| −38.10 | −16.67（最下段は隙間 28.9mm と広い） |

例: 9.53 → 0 → 4.76 → −4.76 → −16.67 と縫うと、段間の横ずれは
最大 12mm・通り道の幅は各段 5.05mm。2 片は約 100mm ＋ 約 90mm になり
A1 mini の実効内寸（168mm 角）に両方収まる。ケース・上ケースには
開口が無いので直線で割れるが、**壁とボスを跨ぐ位置は避けて設計する**。

### 打ち手 C: 外注（JLC 3DP 等）で右の大物だけ刷る

- 印刷容易性: 自宅プリンタの制約から外れる。材質も選べる
- 組み立て容易性: 変化なし
- 費用・リードタイムが発生（未見積もり。#11 の公差クーポンの往復が効かない
  ——外注先の公差は手元と違うので、`CLEARANCE` を外注先で刷った
  クーポンで測り直すことになる）

### 判断に足りていないもの

- **A1 mini に実際に変わるのか**（確定ではない、とのこと）
- 打ち手 B の接合方式の設計・検証（未着手。決まってから）
- 打ち手 C の見積もり

**プリンタが確定するまで設計は変えない。**ただし slice_check は
`--printer a1mini` で今日から両にらみで回せる（K1 Max が既定のまま）。

## 道具の変更

- `tools/slice_check.py` に `--printer a1mini` を追加（既定は k1max のまま）。
  ⚠️ CLI の自動配置の内寸（約168.4mm 角＋斜め可）で判定されるので、
  **「NG＝GUI でも置けない」ではない**。GUI 手動配置の限界は 180 弱。
  逆に「OK＝安定して刷れる」でもない（ベッド端 0.15mm ではスカートも
  引けない）。この検査の NG は「自動配置で入らない」の意。
