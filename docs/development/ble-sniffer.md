# 余った XIAO を BLE のスニッファにする

**無線に実際に何が流れたかを見る。**RTT（ファームの中）でもロジアナ
（基板上の電気）でも見えない層。

**いちばんの用途は [27Hz のジッタ](rtt-debugging.md)**——
「PC が何 Hz で読みに来るか」は、この道具でしか直接は見えない。

---

## 0. 先に用意するもの（**どちらも未インストール・2026-10-15 時点**）

| | 入手先 | 用途 |
|---|---|---|
| **Wireshark** | https://www.wireshark.org/download.html | 取ったパケットを見る |
| **nRF Sniffer for Bluetooth LE** | https://www.nordicsemi.com/Products/Development-tools/nRF-Sniffer-for-Bluetooth-LE | XIAO に焼くファーム＋Wireshark の拡張 |

⚠️ **どちらも利用者が入れる必要がある**（この環境には無い）。
nRF Sniffer は Python スクリプトを Wireshark の `extcap` へ置く作りなので、
**GUI の操作が要る。**ここは自動化できない。

---

## 1. できること・できないこと

**できる**:

- **接続間隔**（connection interval）と latency を実測する
- 実際に飛んだパケット数、スキップされた回数
- 広告（advertising）の中身とタイミング

**できない**（先に知っておくこと）:

| 制約 | 中身 |
|---|---|
| **1 本の接続しか追えない** | 左⇄右 と 左⇄ホスト を**同時には見られない**。どちらか選ぶ |
| **接続の開始を捉え損ねると追えない** | `CONNECT_IND` から見ていないとダメ。**ペアリングからやり直す**運用になる |
| 暗号化 | 中身を復号できるのは、ペアリングを最初から観測できたときだけ |

→ **27Hz を追うなら「左⇄ホスト」を選ぶ。**右との接続は RTT で見える。

---

## 2. 手順

1. Wireshark と nRF Sniffer を入れる（上記）
2. **XIAO に nRF Sniffer のファームを焼く**
   - 配布物の `hex/` にある nRF52840 用を使う
   - ⚠️ **この XIAO は普通の UF2 では焼けないことがある。**
     [xiao-flash-recovery.md](../hardware/xiao-flash-recovery.md) に、
     **スニッファ用に使った XIAO は SoftDevice が消える**という記録がある
     （＝元の用途に戻すときは復旧手順が要る）
   - **SWD からも焼ける**（[rtt-debugging.md](rtt-debugging.md) の
     `probe-rs download`）。USB が死んでいてもこちらなら入る
3. nRF Sniffer の `extcap` スクリプトを Wireshark に置く（配布物の手順どおり）
4. Wireshark を開くと、インタフェース一覧に **nRF Sniffer** が出る
5. 対象のデバイス（`SSKB_1` など）を選んで取り始める
6. **その状態で左右の電源を入れ直し**、接続の最初から記録する

---

## 3. 何を見るか（27Hz の件）

記録済みの見立て（左→PC の BLE HID 送出で約 6 割が届いていない）に対して、
**どれが本当かを 1 回で判定できる。**

| 見るもの | 意味 |
|---|---|
| `LL_CONNECTION_UPDATE_IND` の `Interval` | **PC が実際に使っている接続間隔。**27Hz = 37.5ms なら、ここが 30 になっているはず |
| `Latency` | ZMK は 30 を希望している。PC がそれを飲んでいるか |
| 空パケット（Empty PDU）の割合 | 間隔は足りているのに**送るものが無い**のか、送れていないのか |
| 再送（`MD` フラグ・同じ `SN`/`NESN`） | **届かなくて再送しているか**。これが多ければ電波環境 |

**これで「PC の設定の問題」か「こちらの送出の問題」かが分かれる。**
ZMK の `hog.c` は失敗したレポートを捨てる（再送しない）ので、
**再送が見えない＝取りこぼしが本当に起きている**という読み方になる。

## 4. 現物の状態（2026-10-15）

**スニッファに使う予定だった XIAO が、USB で認識されない。**

- 出荷時ファームの LED（赤→緑→青のゆっくり巡回）は正常＝**電源は来ている**
- リセット 2 回押しで LED は消えるが、**ブートローダのドライブが出ない**
- `ioreg` の USB 一覧に**一切現れない**
- **同じケーブル・同じポートで別の XIAO は正常にマウントする**
- 外観: **USB コネクタが基板に対して斜めに実装され、端子のはんだ付けにずれ**

→ **製造不良として千石電商（購入元）へ問い合わせ済み。返事待ち。**

**代わりに SWD で中を読むこともできる**（[rtt-debugging.md](rtt-debugging.md)）。
`probe-rs info` でチップが応答するかを見れば、
**ブートローダの問題か、チップ自体の不良か**が分かる。
Pico の線を繋ぎ替えるだけで、半田付けは要らない（押し当てでも読める）。
