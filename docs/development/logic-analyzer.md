# ロジアナで基板上の電気を見る

**RTT（ファームの中）では見えない層。**実際にピンがどう振れたか。

---

## 0. 先に用意するもの（**未インストール・2026-10-15 時点**）

**Logic 2**（Saleae）: https://www.saleae.com/pages/downloads

この環境に `.mcp.json` 相当の設定だけはある:

```json
"logic2": { "type": "http", "url": "http://127.0.0.1:10530" }
```

**つまり Logic 2 を起動すれば、私（AI）が直接キャプチャを読める。**
いまは `ECONNREFUSED`＝**アプリが入っていない**（`/Applications` に無い）。

> Logic 2 の設定で **Automation Server を有効にし、ポートを 10530** にすること
> （既定は 10430 のことがある。合わないと繋がらない）。

---

## 1. 何を見るか（**この案件で未実測のまま残っているもの**）

### (a) デバウンスの値（**推測のまま 2 ヶ月**）

`hhkb_split_right.conf` にこう書いてある:

```
# **Type-S に寄せるなら押しは短い方がよいが、短すぎるとチャタリングを拾う。**
# 押し 3ms / 離し 5ms から始め、Task C2-b の実測で詰める。
CONFIG_ZMK_KSCAN_DEBOUNCE_PRESS_MS=3
CONFIG_ZMK_KSCAN_DEBOUNCE_RELEASE_MS=5
```

**「実測で詰める」と書いたまま、まだ測っていない。**
行のピンを見れば、実際のチャタリングの長さが分かる。
3ms が足りているのか、過剰なのかを数字で言える。

### (b) SPI（595 の列駆動）

```
spi-max-frequency = <4000000>;   /* 4MHz */
```

- 本当に 4MHz で出ているか
- **立ち上がりが鈍っていないか**（配線が長い・容量が大きい）
- CS（D7）と SCK/MOSI の順序

### (c) 走査の周期と、キーが拾われる瞬間

RTT で `Sending event at 3,5` は見えるが、**その手前の電気**は見えない。
列を駆動してから行を読むまでの待ち（`WAIT_BEFORE_INPUTS`）が
足りているかは、波形でしか分からない。

---

## 2. どこに当てるか

| 信号 | XIAO のピン | 見たいこと |
|---|---|---|
| `SPI_SCK` | **D8** | 4MHz 出ているか・波形の鈍り |
| `SPI_MOSI` | **D10** | 595 へ送る列パターン |
| `CS`（ラッチ） | **D7** | 転送の区切り |
| `ROW0`〜`ROW4` | **D2〜D6** | **チャタリングの実測**（(a)） |

出典: [`hhkb_split.dtsi`](../../config/boards/shields/hhkb_split/hhkb_split.dtsi)
のピン割り当て表。

⚠️ **GND を必ず共通にする。**ロジアナの GND を XIAO の GND へ。

⚠️ **`VBATT_SENSE`（D0）には当てない。**1MΩ+1MΩ の分圧なので、
プローブの入力容量で読みが狂う。電池電圧は RTT のログで見る。

---

## 3. 見えないもの

**無線は見えない。**27Hz のジッタは「PC が何 Hz で読みに来るか」の話なので、
**ロジアナでは原理的に追えない**。あれは [BLE スニッファ](ble-sniffer.md)。

---

## 4. 手順（Logic 2 を入れたあと）

1. Logic 2 を起動し、Automation Server を有効化（ポート 10530）
2. この会話で `logic2` の MCP が繋がる
3. プローブを上の表のピンへ。**GND を忘れない**
4. 取る → 私が読む

**キャプチャを私が直接読めるので、「波形を言葉で説明してもらう」必要が無い。**
これが RTT と同じ利点。
